## 二、開發過程

### 1. 簡報編號與排列

- 每份簡報標題加上編號：`01｜開店＝慢性死亡？` … `10｜230 元的便當怎麼賣？`。
- 03 原本的資料夾 `six-things-before-opening` 沒有編號，改名為 `03-six-things-before-opening`（網址跟著變成 `/s/03-six-things-before-opening`），`tools/backcheck.mjs`、`tools/livecheck.mjs` 同步更新。
- open-slide 首頁預設「最新優先」排序，所以把 01～10 的 `meta.createdAt` 刻意設成 01 最新、10 最舊，預設畫面就是 01→10。這不是真實建立時間。

### 2. 學員版需求與決策

使用者提出四點：只看得到已公開的部分、點了直接播放、16:9 直接播放、先討論再執行。討論後的決定：

| 問題 | 決定 |
|---|---|
| 公開怎麼控制 | 清單檔控制（後來確定為標記檔，見第 4 節） |
| 學員站網址 | 同一個 repo 的子路徑 `/student/` |
| repo 公開的風險 | 方案 A：維持公開（原始碼與講者備註在 GitHub 上看得到，使用者知情接受） |
| 講師站 | 加簡易密碼 |
| 播放功能 | 點進去自動全螢幕、手機滑動翻頁、PDF 下載、顯示頁碼 |
| 每頁評價 | 星星評價，累積每頁平均；另計每份簡報瀏覽次數；匿名；星星放右下角 |

### 3. 架構

**講師站**：沿用 open-slide 原生建置。建置後由 `tools/add-gate.mjs` 在 `dist/index.html` 注入：

- 密碼畫面：只存密碼的 SHA-256，在瀏覽器端比對；通過後同一台裝置記住。
- 首頁右下角「學員站開放清單」面板：顯示 10 份簡報的開放狀態，按鈕連到 GitHub 編輯 `public.json`、開啟學員站。只在講師站首頁出現，播放時不出現。

**學員站**（`student/`，自己寫的 Vite＋React 小程式，不用 open-slide 的編輯介面）：

- 只打包 `public.json` 列出的簡報；沒列的完全不進學員站檔案。
- 每份簡報只轉出頁面、配色、標題，**講者備註（`notes`）不打包**。
- 直接取用 open-slide 掛在 `globalThis` 的頁碼與分段（`<Steps>`）context，所以簡報原始碼不用改。
- 網址用 `#/01/5`（hash 路由），GitHub Pages 不需要伺服器轉址。
- 播放：1920×1080 畫布等比縮放、黑邊補滿；鍵盤 ← → 、手機左右滑、控制列按鈕翻頁；分段內容先逐段出現再換頁；翻牌卡學員可自己點。
- 右下角控制列（貼著簡報畫面定位、放在頁尾線上方，不蓋住簡報自己的頁碼）：回首頁、上一頁／下一頁、頁碼、星星評價與平均；平常半透明，滑鼠移上去才清楚；手機上自動縮小。
- 首頁卡片：編號、封面縮圖、標題、頁數、瀏覽次數、PDF 下載。

**評價後端**（`student/apps-script.gs`，綁在使用者的 Google 試算表）：

- 工作表：評分紀錄（每台裝置對每頁一筆，匿名，重按覆蓋）、頁面統計（QUERY 公式算人數與平均）、瀏覽次數（同一分頁視窗重複開只算一次）。
- 學員端在背景送出，用 `text/plain` 避免跨網域預檢；按星星畫面立即變化，不等 Google 回應。

**部署**（`.github/workflows/pages.yml`）：`npm run build` → `node tools/add-gate.mjs` → 複製 `404.html` → `npx vite build --config student/vite.config.ts`。

### 4. 開放設定的兩次調整

1. **第一版：Google 試算表即時開關**。講師站面板每份簡報一個開關，存到試算表「公開設定」工作表，Apps Script 驗證講師密碼，學員站開啟時再向試算表問清單。為了即時切換，10 份簡報都得打包進學員站。
2. **實測問題**：Apps Script 回應時間不穩，通常 2～3 秒，偶爾 10～30 秒，也會偶發失敗；學員站首頁要等清單才能顯示。曾加上「記住上次清單、背景更新」緩解，但存開關仍慢且容易失敗。
3. **定案：標記檔**。使用者同意改回 `student/public.json`：在 GitHub 網頁改編號、Commit，約 1～2 分鐘自動部署。好處是穩定、學員站秒開，且未開放的簡報又回到完全不打包。試算表只保留評價與瀏覽次數（背景送出，慢也不影響畫面）。

## 三、驗收

- 本機以 `/open-slide_a01/` 路徑架站實測講師站與學員站；線上部署後再次確認。
- 學員站只出現開放的簡報；直接輸入未開放簡報的網址會回首頁。
- 檢查打包結果：學員站檔案裡找不到講者備註，也找不到未開放簡報的內容。
- 分段內容、翻頁、星星評分、手機橫向（812×375）版面都實際操作過。
- 講師站：密碼錯誤會擋下、正確才放行；開放清單面板顯示正確、連結正確。
- Apps Script：讀取（GET）與寫入（POST）跨網域都能用；只送會被拒絕的測試請求，未寫入測試資料。
- 本機測試時開過一次 09，試算表「瀏覽次數」的 09 多 1 次，已請使用者手動減 1。

## 四、踩過的坑

- **React 被打包成兩份**：簡報檔在 `student/` 外面，路徑大小寫不同讓 React 被當成兩個模組，執行時 `useState` 讀到 null。解法：Vite 設定 `resolve.dedupe: ['react', 'react-dom']`。
- **open-slide 的虛擬模組**：`@open-slide/core` 會引用 `virtual:open-slide/slides`、`virtual:open-slide/config`，學員站要給空的替身模組。
- **Windows Git Bash 改寫路徑**：本機執行 `BASE_PATH=/open-slide_a01/ npm run build` 時，`/open-slide_a01/` 會被改寫成 `C:/Program Files/Git/open-slide_a01/`。要加 `MSYS_NO_PATHCONV=1`。線上（Linux）不受影響。
- **環境變數只在單一步驟有效**：CI 的 `BASE_PATH` 只設在建置步驟，注入面板時讀不到；改成從建置好的 `index.html` 裡的 script 路徑推回網站前綴。
- **GitHub Pages 快取**：部署完 10 分鐘內，瀏覽器可能拿到舊版；網址加 `?v=...` 可略過快取驗證。
- **控制列位置**：一開始固定在螢幕右下角，會蓋到簡報自己的頁碼；「回首頁」放左上角會蓋到章節進度條。最後全部收進一條控制列，貼著簡報畫面定位在頁尾上方。

## 五、已知限制

- 講師站密碼只在瀏覽器端檢查，能擋一般人，擋不住懂技術的人。
- repo 為公開，原始碼（含所有簡報與講者備註）在 GitHub 上看得到（使用者選擇的方案 A）。要完全保密需改成私人 repo（GitHub Pages 需 GitHub Pro）。
- iPhone 的瀏覽器不支援網頁全螢幕，改成整個視窗播放。
- 改開放清單後約 1～2 分鐘才生效；講師站面板的狀態要等部署完成並重新整理才更新。
- 評價為匿名、以裝置區分；同一人換裝置或清除瀏覽器資料會被當成新的人。
