## 一、固定答案（不再重複詢問）

製作任何一號簡報時，下列問題一律用這些答案，**不要再問使用者**：

| 項目 | 答案 |
|---|---|
| 場合 | 職訓班課程（餐飲創業班） |
| 時長與頁數 | 約 45 分鐘，約 25 頁（可在 22～26 頁之間，章節頁、總結頁翻得快） |
| 聽眾 | 求職待業、正在接受專業技能培訓的職訓班學員；對主題多半沒接觸過或聽過沒用過，從零講起，少用術語 |
| 帶走的東西 | 一個觀念、一個工具、一個行動（三樣都要有） |
| 視覺方向 | 溫暖穩重的甜點店感，沒有 logo；不用彩虹漸層，不要 AI 味 |
| 講者口吻 | 沒有逐字稿可統計，用「職訓班講師、口語、直接」 |
| 數字 | 只能用素材裡出現的數字，另補數字要有來源與取得日期；預設沒有補充 |
| 其他素材 | 預設沒有；有的話使用者會主動給 |

只有「找不到來源檔」或「規則互相衝突」才可以問使用者。

## 三、內容規則

1. **版位公式**：封面 → 開場成果或掛鉤（含便利貼／提問互動）→ 這場不是什麼 → 目錄 → 各主題（每個主題前一頁章節頁，講完一頁深色的一句話總結頁）→ 踩坑分享 → 課堂討論 → QA → 帶走三樣 → 核心一句話收尾。
2. 架構檔頁數少於 22 頁時，用章節頁、總結頁、工具頁、討論頁補足，不灌水；內容多於 26 頁時合併。
3. **講者姓名不出現在簡報上**（含封面、頁尾、備註以外的任何地方），一律改稱「業界創業者」「業界經驗」。連結、課程、頻道、業配資訊也不放。
3-1. **訪談類（09、10 號）**：受訪者與主持人都**匿名**，不寫姓名與品牌名（改稱「一位麵包店老闆」「一位便當店創辦人」「這位老闆」「這位創辦人」），這是使用者決定的。受訪者的營收、成本、人數都是個人自述，旁邊要標「自述，不是統計」；原稿標明是轉述或未查證的數字（例如淨利約 20%）要另外註明。提到個人經歷時用中性、尊重的寫法。簡報 id、PDF 檔名也不放人名。
4. **數字**：先整理「數字底稿」（來源＋性質），簡報上每個數字都要在底稿內；個人經驗的數字旁加小字「經驗值，非統計」。
5. **區分來源**：影片原有的內容直接寫；我們整理推導的建議，旁邊加標籤「延伸建議」。
6. 避免 AI 用語：賦能、驚艷、打造、助力、深耕、閉環、賦予、全方位等。
7. 一頁一個重點；本文字級不小於 40px（正文）、標籤與註記不小於 28px；頁面下半部不留大片空白。
8. 敏感議題（例如自殺、個案店名）：不放店名與事件細節，用「經營者如何面對失敗」的正向角度；必要時附心理支持資源（安心專線 1925）。
9. 講者備註（口白）寫進 `export const notes`，與頁面一一對應；用口語，不是畫面文字的複誦。
10. 帶走三樣的三個東西，要和章節內容對得上：觀念（一句話）、工具（可以當場畫、當場用的東西，要有一頁專屬的工具頁）、行動（回去 24 小時內能做的一件事，通常接回開場的便利貼或提問）。

## 五、互動效果（基本版做完再加）

- **章節進度條**：每頁頂部顯示章節名稱與進度，封面不顯示。頁碼區間集中在檔案裡的 `CHAPTERS` 一處；**增刪、搬移頁面後必須同步更新**。
- **翻牌卡**：點一下以 3D 旋轉翻面。用在「風險 → 後果」「問題 → 答案」這類一翻就懂的內容。元件加上 `data-osd-interactive`，否則點擊會被當成換頁。
- **長截圖燈箱**：只有簡報裡真的有長截圖才做，沒有就不做。點圖放大、可上下捲動，捲動時不可帶動換頁。
- **提醒使用者**：互動元素在編輯畫面點不動，要按 **F** 進播放模式才會動。
- 步驟顯示（`Steps`）只用在「順序就是重點」的頁面，不要每頁都用。

## 六、驗收（交付前必跑）

1. 用自動化瀏覽器逐頁截圖（1920×1080），**自己看每一張**：爆版、對比度、錯字、空白過多。
2. 縮小 50%（960×540）再看一次，模擬視訊會議的畫質。
3. 逐一核對簡報上的數字與「數字底稿」一致。
4. 程式檢查文字有沒有超出版面（`tools/shoot.mjs` 會自動回報）。
4-1. **翻牌卡背面也要檢查**：`shoot.mjs` 只拍正面；要另外跑 `tools/backcheck.mjs`（翻開所有卡片、量背面文字是否超出卡片高度並截圖），並看截圖。背面字級預設 38～40px、卡高 100px，文字一行放不下就會被裁掉。
5. 檢查簡報裡沒有講者姓名、沒有 AI 用語。

## 七、評論迭代（Inspector）

- 使用者在瀏覽器編輯畫面按 **Inspect**，點元素、在 **Comment** 留言，留言會存進程式碼。
- **初修**：使用者從頭到尾整份順一遍，全部留完，**一次套用**；不要留一則改一則。
- **細修**：主結構穩了才逐頁調呈現與動畫。
- **最後**：搭配動畫完整跑一次，模擬真的在講課，把不順或多餘的動畫拿掉。
- 留言落在共用元件（標題、卡片）時，套用會影響全部頁面；先告知使用者，或要求在留言寫明頁碼。
- 套用留言前先確認標記在程式碼裡的位置，並順手移除不小心造成的位移（`translate`）。

## 八、輸出

- **PDF**：用自動化瀏覽器逐頁截圖後合併成 PDF，**不要用瀏覽器列印**（會跑版）。放專案根目錄，檔名 `NN_<主題>_簡報.pdf`。翻牌卡在 PDF 只會顯示正面，要在製作報告註明。
- **圖片**：先壓縮，最長邊約 1500px，沒有透明需求一律轉 jpg。目前簡報插圖都是程式畫的向量，不需要壓縮。
- **上線**：build 出來是純靜態網站，放任何靜態空間都行。目前用 GitHub Pages，分講師站與學員站，見「十、線上網站」。
- **離線備份**：提醒使用者另存一份離線備份（現場網路不好、電腦壞掉時保命）；字型是從網路載入，離線會退回系統字型，版面略有差異。

## 九、技術做法（給之後的我）

- 專案在 `C:\Users\Albert\openslide\my-deck`（不在雲端同步資料夾，因為有 node_modules）；每份簡報一個資料夾 `slides/<id>/index.tsx`，id 用 `NN-英文短名`。
- 開發伺服器：在專案資料夾執行 `npm run dev`，網址 `http://localhost:5173/s/<id>`。
- 工具資料夾 `C:\Users\Albert\openslide\tools\`：
  - `build-deck.mjs`：用共用元件＋色票＋頁面內容組出 `index.tsx`。
  - `shoot.mjs`：逐頁截圖並檢查爆版（走 `/s/<id>/preview?p=N&step=99`）。
  - `sheet.py`：把截圖拼成縮圖總覽，方便一次看多頁。
  - `mkpdf.mjs`：把截圖合併成 PDF。
- 一份簡報只有一個 `index.tsx`，不另外建 `.tsx` 檔；講者備註放 `notes` 匯出。
- 重複的元件（卡片、列）寫成元件各自實例化，不用 `array.map`，這樣 Inspector 才能分別修改。
- 注意：Bash 的 heredoc 遇到長中文內容可能被擋，改用寫檔工具。
- 標題字級統一由 `H` 元件處理（實際字級＝傳入值＋8）；內容區用 `Body` 在標題下方垂直置中。
- 播放模式點擊會換頁；互動元件要加 `data-osd-interactive`。
- 做法：每號寫 `tools/pages-NN.tsx.txt`（頁面內容與講者備註）＋ `tools/chapters-NN.json`（章節區間），用 `bash tools/run-deck.sh <id> <色票> <標題> <章節檔> <頁面檔> <頁數> <輸出資料夾>` 一次組出、截圖、檢查爆版；`kit-head.tsx.txt`／`kit-parts.tsx.txt` 放所有簡報共用的元件，新增共用元件時一併更新。
- 單次指令不要超過 10 分鐘（一次截 26 頁約 1～2 分鐘）；多份簡報要分開跑。
- 檔案內容含 `\n` 時，用 Python 改檔要寫 `chr(92)+'n'`，否則會被轉成真的換行、造成字串壞掉（開發伺服器會顯示 Unterminated string）。
- 容易爆版的版型：標題下方卡片 ≥ 3 張加提示行（改成 `Body` 靠上並縮小間距）、表格欄位文字過長（每格 ≤ 14 字，或加 `<br />`）。孤字（一行只剩一兩個字）要用手動換行處理。

## 十、線上網站（講師站／學員站）
